# Piper

> Децентрализованная P2P-платформа для защищённой коммуникации с поддержкой mesh-сети, звонков и обмена файлами.

## О проекте

**Piper** — экспериментальная кроссплатформенная система децентрализованной связи, разработанная в рамках `Nuclear IT Hack`.

Проект ориентирован на работу без центрального сервера и использует гибридную P2P + mesh архитектуру для передачи сообщений, файлов и мультимедиа между устройствами.

Основная цель проекта — создать отказоустойчивую, безопасную и автономную систему коммуникации, способную работать даже при нестабильной сети или отсутствии централизованной инфраструктуры.

# Архитектура

Piper использует смешанную архитектуру:

```text
          ┌──────────────┐
          │   Flutter UI │
          └──────┬───────┘
                 │ CGo FFI
          ┌──────▼───────┐
          │  Go Backend  │
          └──────┬───────┘
                 │
      ┌──────────┴──────────┐
      │                     │
┌─────▼─────┐         ┌─────▼─────┐
│ P2P Layer │         │ Mesh Layer│
└─────┬─────┘         └─────┬─────┘
      │                     │
   TCP/UDP             Wi‑Fi Direct
```

## Маршрутизация

Для mesh-сети используется source routing на основе алгоритма Дейкстры.

Вес маршрута вычисляется на основе:

```text
RTT + loss² × 10000 + тип канала
```

### Защита от циклов

Каждый mesh-пакет содержит:

* hop-list
* ограничение количества хопов
* deduplication id

# Передача файлов

### Особенности

* Передача чанками по 512 KB
* Ограничение нагрузки: ~5 MB/s
* Шифрование каждого чанка
* SHA‑256 контроль целостности
* ACK подтверждения

### Шифрование

```text
ChaCha20 + уникальный nonce
```

Real-time звонки реализованы через **WebRTC**.

## Возможности

* Голосовые звонки
* Видеозвонки
* Мониторинг качества соединения

# Почему Go + Flutter?

## Go

* Высокая производительность
* Низкие задержки GC
* Эффективная работа с сетью
* Компактный бинарник
* Отличная поддержка concurrency

## Flutter

* Один код для всех платформ
* Быстрая разработка UI
* Нативная производительность
* Удобная работа с мультимедиа

## CGo FFI

Go и Flutter взаимодействуют напрямую через FFI без HTTP/JSON-прослойки.

Это позволяет:

* уменьшить latency
* снизить overhead
* отказаться от локального API-сервера

# Идея проекта

Piper создавался как система связи, способная:

* работать без центральных серверов
* сохранять коммуникацию при нестабильной сети
* обеспечивать приватность пользователей
* поддерживать mesh-networking
* масштабироваться без единой точки отказа

Проект исследует возможности современных P2P-технологий, mesh-routing и локальной децентрализованной коммуникации.
